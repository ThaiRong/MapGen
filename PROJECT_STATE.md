## Сейчас делаем
Итерация 5 (профили сеттинга) реализована:
- модель: SettingProfile (категории, типы легенды, правила имён со
  шаблонами и списками слов, виды локаций и местности); профиль — чистые
  данные, в ядре нет ни одного сеттингового слова; формат проекта v2
  (v1 мигрирует идемпотентно);
- библиотека ~/.mapgen/profiles/<id>.json с индексом (Rust-команды
  profile_*), создание/дублирование/удаление/импорт/экспорт; конфликт id
  при импорте решается новым id; битый файл — понятная ошибка, не краш;
- самодостаточность: при применении профиля в проект встраивается
  profileSnapshot; генерация и именование работают от снапшота, файл
  профиля можно удалить; при отсутствии файла — ненавязчивое уведомление;
- применение профиля: типы по id (стиль обновляется, shape конфликт
  используемых типов блокирует с объяснением), одна запись истории;
  отключение снимает activeProfileId, типы и примитивы целы;
- редактор профиля: окно «Профили» (список с поиском + разделы: общее,
  категории, типы, правила имён с живыми примерами, виды локаций и
  местности с детерминированным предпросмотром на canvas);
- генерация через виды: селекты «Вид местности»/«Вид локации» (из
  снапшота), подстановка параметров и маппинга; правила имён вшиваются
  в спеку (воспроизводимость); вложенные маркеры получают kindId из
  nestedKindId; переименованный сгенерированный объект становится manual
  и переживает перегенерацию.

Проверено: tsc, vite build, cargo check, смоук-тест 220/220 (имена:
детерминизм, фолбэк; валидация профилей: битые ссылки, дубли, циклы;
применение: добавлено/обновлено, конфликты, защита manual/locked;
самодостаточность снапшота; миграция v1; отключение).
Ждём следующую команду.

Примечание: на машине разработчика корпоративный Kaspersky блокирует
запуск свежесобранных exe внутри `C:\Users\WinBug\MapGen` (os error 32).
Обход: собирать с `CARGO_TARGET_DIR=%LOCALAPPDATA%\Temp\mapgen-target`
(см. scripts/tauri-dev.bat и scripts/cargo-vs.bat).
