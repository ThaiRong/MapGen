# PIPELINE

Автономный пайплайн разработки локального генератора карт для НРИ.
Итерации 1–5 выполнены. Дальше — итерации 6–11 по порядку.

## Общие принципы (действуют для всех итераций)

1. Полный офлайн. Никаких сетевых запросов в runtime, CDN, внешних шрифтов, телеметрии.
   Исключение: локальный Ollama через 127.0.0.1/localhost, только опционально и только при явном включении пользователем (итерация 6).
2. Сеттинг-агностичное ядро. В коде генераторов и ядра нет слов «фэнтези», «таверна», «гоблин», «лес», «река», «город», «комната», «станция». Смыслы приходят только из пользовательских данных.
3. Пресеты и словари пусты по умолчанию. Всё создаёт пользователь.
4. Ручная работа защищена. Примитивы с origin='manual' и locked=true никогда не удаляются и не изменяются генерацией.
5. Разрушительные действия — только с подтверждением и точными числами.
6. История изменений. Значимые действия пишутся в журнал, интегрированы с undo/redo. Генерация — одна запись.
7. Интерфейс на русском, нейтральный тёмный, без стилизации.
8. Любая генерация детерминирована: один seed + один spec = идентичный результат. Никакого Math.random в генераторах.

## Протокол состояния

Состояние хранится в PROJECT_STATE.md. Формат:
- список итераций со статусами [done] / [next] / [todo] / [blocked];
- для последней выполненной — дата и краткий итог;
- раздел «Блокеры», если есть.

Правила обновления:
- статус меняется только после прохождения проверок итерации;
- нельзя ставить [done] без выполненных проверок;
- при блокере итерация получает [blocked] с описанием причины.

## ИТЕРАЦИЯ 6 — Локальная модель: текст → structured spec

Цель: пользователь пишет свободное описание, локальная модель переводит его в валидный GenerationSpec или StructureSpec. Геометрию по-прежнему строит детерминированный генератор. Модель никогда не рисует сама.

Фазы:
6.1 Адаптер модели. Интерфейс `ModelAdapter` с методами `isAvailable()`, `parseDescription(text, schema) -> SpecSuggestion`, `listModels()`. Реализация через локальный HTTP на 127.0.0.1 к Ollama. Только последняя версия Ollama. Адаптер изолирован: ядро и генераторы от него не зависят и не знают о нём.
6.2 Структурированный вывод и валидация. Модель возвращает JSON по схеме спеки. Результат валидируется существующими контрактами из итераций 3 и 4. Невалидный результат отбрасывается с понятной ошибкой, ничего не применяется.
6.3 Предпросмотр распознанного. Перед применением показывается разобранный spec: какие параметры распознаны, какие значения предложены, какое зерно. Пользователь подтверждает или правит вручную. Ничего не применяется молча.
6.4 Настройки и фолбэк. Панель настроек: включить/выключить модель, выбор модели, проверка соединения, статус. Модель выключена по умолчанию. Если модель недоступна, выключена, вернула ошибку или таймаут — приложение молча возвращается к существующей форме параметров. Деградация бесшовная.

Ограничения:
- только 127.0.0.1/localhost, никаких внешних эндпоинтов;
- модель не создаёт примитивы, не меняет легенду, не пишет в историю до подтверждения пользователя;
- зерно всегда явное и редактируемое; распознанный spec — предложение, не приказ;
- веса модели локальные, ничего не скачивается в runtime.

Критерии:
1. Включить модель в настройках, проверка соединения показывает статус.
2. Ввести описание, получить предпросмотр распознанного spec.
3. Подтвердить — спека применяется к существующей панели генерации.
4. Отключить модель — форма параметров работает как раньше.
5. Сломать/отключить Ollama — приложение не падает, предлагает форму параметров.
6. Невалидный ответ модели не применяется и не ломает проект.
7. В коде генераторов не появилось зависимости от модели.

Проверки: tsc, сборка, cargo check, тест валидации ответа модели, тест фолбэка при недоступной модели, тест детерминизма (распознанный spec + зерно дают воспроизводимый результат).

## ИТЕРАЦИЯ 7 — Туман войны

Цель: мастер скрывает и раскрывает части карты. Туман работает на каждой карте дерева. Архитектура сразу рассчитана на проекцию для окна игрока в итерации 8.

Категории тумана (независимые маски):
- ландшафт;
- топография;
- интерактивные элементы.

Фазы:
7.1 Модель тумана. На каждую карту — три маски (ландшафт/топография/объекты). Хранение компактное (RLE или побитово), сериализация в .mapkg, миграция старых карт (туман по умолчанию раскрыт).
7.2 Кисть. Инструмент тумана: радиус, режим раскрыть/скрыть, чекбоксы категорий, инверсия по Alt. Рисование по маске. Один штрих или группа штрихов — одна запись истории.
7.3 Отображение мастера. Мастер видит всю карту, скрытые зоны показаны деликатным оверлеем, чтобы не терять контекст. Оверлей включается/выключается.
7.4 Семантическое раскрытие и массовые операции. Раскрыть/скрыть всё по выбранным категориям. Раскрыть сущность целиком по клику (улица, область, маркер). Инверсия.
7.5 Подготовка к проекции. Видимость сущности для игрока считается как пересечение маски нужной категории и флага разрешения. Данные для игрока фильтруются до отправки, а не скрываются стилем. В этой итерации окно игрока ещё не создаётся, но функция проекции реализуется и тестируется.

Ограничения:
- туман не удаляет сущности, только скрывает;
- ручные и заблокированные сущности скрываются туманом наравне с прочими, но не удаляются;
- скрытый объект не передаётся в проекцию игрока вообще, вместе со своими названиями и заметками.

Критерии:
1. Раскрыть/скрыть область кистью по каждой из трёх категорий независимо.
2. Туман сохраняется после перезагрузки.
3. Раскрыть сущность целиком одной операцией.
4. Раскрыть всё / скрыть всё / инвертировать.
5. Отменить штрих тумана через Ctrl+Z.
6. Туман работает на глобальной карте и на вложенных локациях.
7. Функция проекции возвращает только раскрытые и разрешённые сущности (проверяется тестом).

Проверки: tsc, сборка, cargo check, тест сериализации масок, тест проекции (скрытая сущность не попадает в результат), тест независимости категорий, миграция старых карт.

## ИТЕРАЦИЯ 8 — Окно игрока

Цель: второе окно, в котором игрок видит только раскрытое туманом и явно разрешённое мастером. Мастер управляет, игрок смотрит.

Фазы:
8.1 Второе окно. Tauri multiwindow. Окно игрока открывается отдельной кнопкой и перетаскивается на второй монитор. Рендер через тот же Canvas 2D.
8.2 Проекция. Окно игрока получает ТОЛЬКО отфильтрованную проекцию из итерации 7. Скрытые туманом сущности, а также сущности с флагом «не показывать игрокам», не передаются вовсе — ни геометрия, ни названия, ни заметки. Фильтрация выполняется в основном процессе до передачи в окно.
8.3 Режимы просмотра. Окно игрока: собственный pan/zoom, опция «следовать за камерой мастера», счётчик видимых объектов, фильтруемая легенда (только типы, у которых есть видимые объекты).
8.4 Управление видимостью. Мастер переключает для маркера/примитива флаг «показывать игрокам». Скрытые от игрока объекты на холсте мастера помечаются визуально, но не удаляются.
8.5 Синхронизация. Изменения карты, тумана и флагов видимости оперативно отражаются в окне игрока. Обновление троттлится, чтобы не блокировать интерфейс.

Ограничения:
- окно игрока только для просмотра, без инструментов редактирования;
- игрок не может открыть инспектор, дерево карт, заметки мастера;
- никаких данных «про запас»: в окно игрока не сериализуется ничего скрытого;
- закрытие окна игрока не влияет на проект.

Критерии:
1. Открыть окно игрока, перетащить на второй монитор.
2. Скрытая туманом область не видна игроку.
3. Объект с флагом «не показывать» не виден игроку, даже если туман раскрыт.
4. Легенда игрока показывает только типы с видимыми объектами.
5. Переключение видимости мастером сразу отражается у игрока.
6. Раскрытие тумана мастером появляется у игрока.
7. «Следовать за камерой мастера» работает и отключается.
8. В окне игрока нет инструментов, дерева и заметок.

Проверки: tsc, сборка, cargo check, тест проекции (скрытое не попадает), тест фильтрации легенды, тест синхронизации, миграция.

## ИТЕРАЦИЯ 9 — Сетка, рулетка, масштаб, привязки

Цель: измерительные инструменты и настраиваемая сетка. Конвертация участка региональной карты в баттл-сцену.

Фазы:
9.1 Настраиваемая сетка на карту. Тип квадрат/гекс, размер, цвет, прозрачность, подписи координат, включение/выключение. Настройки хранятся на карте.
9.2 Масштаб. Единицы на клетку и подпись единиц («км», «м», «мили», «футы», «сектора»). Хранится на карте, влияет на рулетку и подписи.
9.3 Рулетка. Инструмент измерения: клик-клик, отрезки с подписью расстояния, итоговая длина. Режимы: по прямой; с учётом единиц масштаба. В баттл-режиме — в клетках и футах. Измерения — только для мастера, не передаются игроку.
9.4 Конвертация региона в баттл-сцену. Инструмент выделяет прямоугольник на карте и разворачивает его в отдельную баттл-карту с сеткой. Если в области есть сущности — они переносятся/адаптируются. Связь с исходной картой сохраняется.
9.5 Привязки. Опциональный снап сущностей и маркеров к сетке при перемещении. Включается/выключается.

Ограничения:
- рулетка и измерения не попадают в окно игрока;
- конвертация в баттл не удаляет исходную карту и не затирает ручную работу;
- снап опционален и не ломает свободное перемещение.

Критерии:
1. Включить квадратную и гексагональную сетку, менять размер и прозрачность.
2. Задать масштаб, рулетка считает в выбранных единицах.
3. Измерить расстояние из нескольких отрезков, увидеть итог.
4. Выделить область и развернуть в баттл-сцену с сеткой.
5. Вернуться из баттл-сцены к исходной карте.
6. Включить снап, переместить объект — он прилип к сетке.
7. Измерения не видны в окне игрока.

Проверки: tsc, сборка, cargo check, тест конвертации (ручная работа сохраняется), тест единиц рулетки, тест снапа, миграция.

## ИТЕРАЦИЯ 10 — Токены и состояния + библиотека иконок

Цель: 2D-токены для баттл-сцен с состояниями, библиотека токенов и библиотека иконок для легенды. Всё офлайн, процедурно, без генеративных моделей.

Фазы:
10.1 Библиотека иконок. Встроенный набор иконок, построенный комбинаторно из глифов и оправ, чтобы получить порядка 200 уникальных иконок без ручной отрисовки каждой. Иконки назначаются типам легенды и маркерам. Рендер через Canvas/SVG локально.
10.2 Процедурный композитор токенов. Бумажная кукла из слоёв: силуэт, расцветка, снаряжение, оружие, головной убор. Детерминированный seed: один seed — один узнаваемый персонаж. Вид сбоку. Без внешних ассетов и без диффузионных моделей.
10.3 Состояния. Базовые состояния: стоит, лежит, мёртв. Пользователь может добавлять свои состояния как детерминированные трансформации базового изображения (поворот, оттенок, обесцвечивание, бейдж). Одна личность — один базовый образ, состояния выводятся из него, а не генерируются заново.
10.4 База токенов. Хранение локально. Поиск, фильтр по категориям, сортировка, переупорядочивание. Постановка токена на карту перетаскиванием или кликом. Размер в клетках, снап к сетке в баттл-режиме.
10.5 Управление на карте. Выбор, перемещение, поворот, смена состояния, дублирование, «отряд ×4». Быстрое меню смены состояния. Флаг «показывать игрокам» для каждого токена. Токены — это сущности, защищённые историей и туманом как прочие.

Ограничения:
- никакого скачивания изображений и никаких генеративных моделей;
- токены наследуют защиту: ручные/заблокированные не затираются;
- скрытые от игрока токены не передаются в окно игрока;
- состояния — детерминированные трансформации, не новые генерации.

Критерии:
1. Создать токен в композиторе, задать цвета, снаряжение, сохранить в базу.
2. Найти токен поиском и фильтром, переупорядочить в базе.
3. Поставить токен на баттл-карту, он прилип к сетке.
4. Переключить состояния стоит/лежит/мёртв.
5. Добавить своё состояние и применить.
6. Дублировать токен и сделать отряд ×4.
7. Скрыть токен от игрока — он не виден в окне игрока.
8. Назначить иконку типу легенды из библиотеки.

Проверки: tsc, сборка, cargo check, тест детерминизма токена (один seed — один образ), тест состояний, тест снапа, тест видимости игроку, миграция.

## ИТЕРАЦИЯ 11 — Импорт схем и картинок

Цель: мастер может подложить нарисованную от руки или найденную схему как референс и обвести её, либо автоматически векторизовать тёмные контуры.

Фазы:
11.1 Подложка. Загрузка изображения как подложки под карту: непрозрачность, видимость, удаление. Подложка видна только мастеру и никогда не передаётся игроку.
11.2 Векторизация контуров. Пороговая бинаризация тёмных линий, поиск контуров, преобразование в редактируемые линии типа «Контур схемы». Упрощение, удаление шума. Результат — обычные примитивы, которые можно править.
11.3 Обводка вручную. Инструменты рисования из итерации 2 уже позволяют обводить подложку. На этой итерации добавляется удобное переключение видимости подложки и привязка к её контрастным краям при желании.

Ограничения:
- только локальная обработка изображения, никаких внешних сервисов;
- без тяжёлых CV-библиотек: достаточно порога и контуров;
- подложка не попадает в окно игрока и в экспорт для игрока;
- векторизация создаёт обычные примитивы и подчиняется защите ручной работы.

Критерии:
1. Загрузить картинку как подложку, менять непрозрачность.
2. Векторизовать тёмные контуры в редактируемые линии.
3. Отредактировать полученные линии обычными инструментами.
4. Подложка не видна в окне игрока.
5. Удалить подложку без потери примитивов.

Проверки: tsc, сборка, cargo check, тест векторизации на синтетическом изображении, тест изоляции подложки от игрока, миграция.
