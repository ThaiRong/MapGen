========================
ОБЩАЯ ИДЕЯ ПРОДУКТА
========================

Нужен локальный offline-генератор карт для НРИ.

Ключевые принципы:

1. Приложение работает локально, без доступа к сети.
   - Никаких CDN.
   - Никаких внешних шрифтов.
   - Никаких удалённых API.
   - Никаких сетевых запросов в runtime.
   - Все ассеты локальные.
   - На этапе разработки можно использовать npm/cargo, но готовое приложение запускается offline.
   - Будущая интеграция с локальным Ollama через 127.0.0.1/localhost допустима только опционально и только при явном включении пользователем.

2. Генератор сеттинг-агностичный.
   - В ядре нет зашитых понятий «фэнтези», «таверна», «гоблин», «лес», «подземелье», «космостанция».
   - Ядро знает только универсальные сущности: карта, маркер-локация, точка, линия, область, подпись, тип легенды, запись истории.
   - Сеттинг позже задаётся пользовательским профилем/легендой/правилами генерации.

3. Локации — отдельные карты, отмеченные на глобальной карте.
   - Глобальная карта — обычная корневая карта.
   - Маркер-локация ссылается на другую карту (targetMapId).
   - Локация — полноценная карта со своим именем, масштабом, сущностями, историей и навигацией.
   - Произвольная вложенность: мир → регион → город → район → здание → комната.
   - Переход внутрь и возврат — базовая навигация.
   - Удаление маркера НЕ удаляет связанную карту.
   - Удалённый маркер восстанавливаем.

4. Два равноправных пути создания карт:
   - автоматически генератором (позже);
   - вручную пользователем (уже работает для маркеров, расширяется на примитивы).
   - Ручной путь — полноценный, не запасной.

5. Локальная модель — позже.
   - Ollama, только последняя версия.
   - Модель переводит текст в structured spec.
   - Геометрию строит детерминированный генератор.
   - Сейчас Ollama НЕ подключать.

6. Пресеты пустые по умолчанию.
   - Нет встроенных фэнтези-пресетов, биомов, локаций, сеттингов.
   - Пользователь сам создаёт типы легенды, категории, профили.

7. История изменений — часть безопасности пользователя.
   - Отмена, повтор, журнал, переход к состоянию, восстановление удалённого.
   - Это пользовательский инструмент, а не технический лог.

========================
МОДЕЛЬ ДАННЫХ (ТЕКУЩАЯ)
========================

Project:
- format: "mapgen-project"
- version
- id, title
- rootMapId
- maps: Record<MapId, MapNode>
- legend: типы легенды (добавляется в фазе 2.1)
- history / архив удалённых маркеров (уже есть)
- createdAt, updatedAt

MapNode:
- id, name
- parentId: string | null
- scale?: { enabled, unitsPerWorldUnit?, unitLabel? }
- entities: Entity[] (маркеры-локации)
- primitives: PrimitiveEntity[] (добавляется в фазе 2.1)
- view?: { centerX, centerY, zoom }
- createdAt, updatedAt

LocationLinkEntity:
- id, kind: "location-link"
- x, y, label
- targetMapId
- флаг удалённости / архив (уже есть)
- createdAt, updatedAt

PrimitiveEntity (фаза 2.1):
Общие поля: id, kind, name, typeId, note, visible, locked, createdAt, updatedAt.
kind: point | line | area | label
- point: x, y
- line: points[] (минимум 2)
- area: points[] (минимум 3, замкнута)
- label: x, y, text, fontSize?

LegendType (фаза 2.1):
- id, name, category
- shape: point | line | area | label
- color, opacity, strokeWidth
- strokeStyle: solid | dashed
- visible
- createdAt, updatedAt

Базовые нейтральные типы по умолчанию (ровно 4):
Точка, Линия, Область, Подпись — категория «Базовые».
Никаких «лес», «дорога», «стена», «вода», «река», «город», «комната».

HistoryEntry (уже есть):
- id, timestamp, operationType, description
- mapId?, entityId?
- снимок состояния или ссылка на состояние
- restoreInfo для восстановления маркеров

Маркеры и примитивы не смешивать в одну сущность; хранить раздельно или через понятный дискриминатор.
