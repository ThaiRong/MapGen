========================
ОБЩАЯ ИДЕЯ ПРОДУКТА
========================

Нужен локальный offline-генератор карт для НРИ.

Ключевые принципы:

1. Приложение работает локально, без доступа к сети.
   - Никаких CDN.
   - Никаких внешних шрифтов.
   - Никаких удалённых API.
   - Никаких сетевых запросов в runtime.
   - Все ассеты должны быть локальными.
   - На этапе разработки можно использовать npm/cargo для установки зависимостей, но готовое приложение должно запускаться offline.

2. Генератор должен быть сеттинг-агностичным.
   - В ядре не должно быть зашитых понятий вроде «фэнтези», «таверна», «гоблин», «средневековый город».
   - Ядро знает только универсальные сущности: карта, точка, линия, область, подпись, ссылка на другую карту.
   - Сеттинг должен позже задаваться пользовательским профилем/легендой/правилами генерации.
   - Сейчас НЕ нужно реализовывать генерацию фэнтези-мира.

3. Локации — это отдельные карты, отмеченные на глобальной карте.
   - Глобальная карта — обычная карта.
   - На ней могут быть маркеры-ссылки на другие карты.
   - Локация — полноценная карта со своим именем, масштабом, сущностями и навигацией.
   - Должна поддерживаться произвольная вложенность:
     мир → регион → город → район → здание → комната.
   - Переход внутрь локации и возврат назад — базовая навигация.

4. Локации могут создаваться двумя путями:
   - автоматически генератором;
   - вручную пользователем.
   На итерации 1 нужен только ручной путь:
   пользователь ставит маркер на карте, создаётся дочерняя карта-локация.

5. Локальная модель будет использоваться позже.
   - Планируется Ollama, только последняя версия.
   - Модель будет переводить текстовое описание в structured spec.
   - Геометрию будет строить детерминированный генератор.
   - На итерации 1 НЕ подключай Ollama и не делай LLM-интеграцию.
   - Но в архитектуре оставь место для будущего адаптера локальной модели.

6. Пресеты должны быть пустыми по умолчанию.
   - Не создавай встроенные фэнтези-пресеты.
   - Пользователь сам будет создавать профили и пресеты.
   - На итерации 1 пресеты не реализовывать, только не зашивать контент.

ЧТО НУЖНО СДЕЛАТЬ СЕЙЧАС
========================

ИТЕРАЦИЯ 1: каркас проекта и иерархия карт.

Нужно реализовать:

1. Создание нового проекта.
   - При первом запуске создаётся проект с корневой картой.
   - Корневая карта называется «Глобальная карта».
   - Проект имеет id, название, версию формата, дату создания/обновления.

2. Дерево карт.
   - Слева панель дерева карт.
   - Корневая карта всегда есть.
   - Дочерние карты отображаются вложенно.
   - Произвольная глубина вложенности.
   - Клик по карте в дереве открывает её.
   - Можно переименовать карту.
   - Можно удалить карту, но с подтверждением.
   - Удаление карты не должно ломать проект.
   - Если у карты есть дочерние карты, нужно явно предупредить пользователя.

3. Холст карты.
   - Центральная область — canvas.
   - Pan/zoom:
     - колесо мыши — масштаб;
     - перетаскивание средней кнопкой или с зажатым Space — панорамирование.
   - Отображение маркеров локаций.
   - Маркер — точка с подписью.
   - Двойной клик по маркеру открывает связанную карту.
   - Одинарный клик выбирает маркер.
   - Выбранный маркер можно двигать.
   - Delete удаляет выбранный маркер.

4. Ручное создание локации.
   - Инструмент «Добавить локацию».
   - Пользователь кликает по холсту.
   - Создаётся маркер на текущей карте.
   - Одновременно создаётся новая дочерняя карта.
   - Новая карта называется «Новая локация», можно сразу переименовать.
   - Маркер хранит targetMapId.
   - Дочерняя карта хранит parentId текущей карты.
   - Новая карта пустая.
   - После создания можно двойным кликом войти внутрь.

5. Навигация.
   - Хлебные крошки сверху:
     Глобальная карта / Город / Район / Здание
   - Кнопка «Наверх».
   - Двойной клик по маркеру — переход внутрь.
   - Клик по элементу хлебных крошек — переход к соответствующей карте.
   - Активная карта всегда понятна пользователю.

6. Инспектор справа.
   - Если выбрана карта:
     - имя;
     - id;
     - родитель;
     - количество дочерних карт;
     - количество сущностей;
     - масштаб, если задан.
   - Если выбран маркер:
     - название;
     - связанная карта;
     - координаты;
     - кнопка «Открыть локацию»;
     - кнопка «Переименовать»;
     - кнопка «Удалить маркер».
   - Удаление маркера удаляет только ссылку/маркер.
   - Дочерняя карта при этом НЕ удаляется автоматически.
   - Она остаётся в дереве проекта.

7. Масштаб.
   - Масштаб карты опциональный.
   - По умолчанию карта безмасштабная.
   - В инспекторе карты можно включить масштаб:
     - единиц на клетку/условную единицу;
     - подпись единиц, например «км», «м», «мили», «сектора».
   - На итерации 1 масштаб можно просто хранить и отображать.
   - Рулетку НЕ реализовывать.

8. Сохранение/загрузка.
   - Сохранение проекта в локальный файл.
   - Загрузка проекта из локального файла.
   - Автосохранение в локальное хранилище приложения.
   - Формат файла пока может быть JSON.
   - Расширение: .mapkg
   - В будущем планируется JSON + бинарные чанки + LZ4.
   - Сейчас НЕ реализовывай LZ4 и бинарные чанки.
   - Но раздели слой хранения так, чтобы позже можно было заменить формат.

9. Undo/redo.
   - Минимальный стек отмены для:
     - создание маркера/локации;
     - перемещение маркера;
     - переименование;
     - удаление маркера.
   - Ctrl+Z / Ctrl+Y.
   - Кнопки undo/redo в интерфейсе.

10. Базовая устойчивость.
   - Нельзя терять проект при ошибке сохранения.
   - При загрузке повреждённого файла показывать понятную ошибку.
   - Не использовать alert/prompt как основной UX, лучше нормальные inline-поля/модальные окна.
   - Все действия должны давать понятную обратную связь.
